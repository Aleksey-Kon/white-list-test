# Проверка фонового мониторинга на телефоне

Дата: 15 сентября 2026. Телефон Xiaomi/POCO 2201116SG, Android 13, MIUI.
Время ниже — местное, UTC+3. Проверялось отдельное приложение
`com.zvezda4443.testwhitelist.dev`; данные рабочей версии сохранены.

## Воспроизведённые причины

1. В старой сборке разрешение уведомлений было выдано, канал имел importance 4.
   Android показывал исчерпанную квоту выполнения заданий: около четырёх часов
   фоновой работы и `not within quota`. Дополнительного запроса разрешений недостаточно.
2. DEV Worker стартовал в 18:55:48 и завершился только в 18:57:11,
   непосредственно после открытия Activity. Дополнительные отметки локализовали
   ожидание на этапе сетевых запросов. TaskManager SDK 54 не удерживает таймеры
   React Native активными при свёрнутой Activity.
3. При холодном запуске восстановление регистрации в `expo-background-task`
   отменяло текущий Worker (`CancellationException`) и создавало новый с задержкой.
4. Регистрация JS-обработчика должна выполняться в `index.js` до Router:
   запуск из фонового сервиса не обязан монтировать layout или экран.

## Исправления

- `expo-task-manager+14.0.9.patch`: Headless JS token для каждого события,
  освобождение после native `notifyTaskFinishedAsync`, при уничтожении модуля
  и нативный предел удержания в две минуты. Парный JS-обработчик не завершает
  token преждевременно.
- `expo-background-task+1.0.10.patch`: `KEEP` при восстановлении регистрации,
  сохранение существующего Worker и последующая постановка следующего запуска.
- `postinstall` применяет патчи; выбранные Expo-модули собираются из исходников.
- Сохранение настроек/результатов, проверка разрешения и канала, тестовый
  переключатель, отдельный тест доставки, ограниченные по времени запросы.

Первые четыре запуска инициированы `adb shell cmd jobscheduler run -f`: они проверяют
реальный Worker, сеть и доставку, но не точность штатного расписания Android.
На переднем плане оставался `com.miui.home/.launcher.Launcher`.
Системный NotificationManager подтверждает отдельные уведомления приложения.

Для JOB 12 после последнего теста единственным невыполненным условием был
`TIMING_DELAY`; сеть, квота и разрешение фонового выполнения были доступны.
Штатный Worker запустился после минимального времени 19:41:28, выполнил проверку
и поставил JOB 13, минимальное время которого — 19:56:37. Проверяется второй штатный запуск.
